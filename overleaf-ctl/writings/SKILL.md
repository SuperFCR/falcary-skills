# 写作层

论文的发表内容是项目中的 `.tex`；起草和修订先在 `.writing/zh/` 的中文稿里完成，再译为英文写入对应 `.tex`（见第 2 节）。先读已有要求、当前主文件的 `\input`/`\include` 及有关章节，保留模板、命令、标签、引用键和用户选定的结构。现有上下文足够时直接推进，不要求固定轮数的访谈或逐章重复确认。

CLI 不可用时先读 [工具层安装说明](../tools/SKILL.md)，检查安装目录的 `.venv` 与 PATH；不把缺依赖误判成需要重新登记或登录 Overleaf。

## 1. 项目档案与恢复

首次开始实质写作时，已有登记别名用 `overleaf-ctl list` 定位；未登记的本地 Git 项目可直接使用 `--path`，不要求 Overleaf 账号或远端。执行其中一种：

```bash
overleaf-ctl writing init ALIAS
overleaf-ctl writing init --path /absolute/path/to/local-git-paper
```

`ALIAS` 与 `--path` 二选一。路径必须是 Git 项目根目录；普通目录先说明需要 Git 本地隔离，按已获授权初始化 Git 或等待用户决定，不要尝试伪造 Overleaf 登记。

命令只创建缺少的文件，保留已有内容：`project.md`、`outline.md`、`layout.json`、`log.md`，每个章节 TeX 对应的空中文稿 `zh/<章节>.md`，并把 `.writing/` 初始化为独立 Git 仓库（与 Overleaf 仓库分开，不会推送到 Overleaf）。把已知要求和本轮范围填入记录；未知内容标为待补，只在影响当前决策时询问。不要把原样初始化的提示文字当作完成的项目档案。

恢复工作时先读 `project.md`、`outline.md` 和 `log.md` 最近几条，运行 `overleaf-ctl writing status ALIAS` 看各章中英状态，再核对当前主文件和 Git diff。旧项目若有 `progress.md`，作为历史记录读取，新记录写进 `log.md`。`layout.json` 是初始化时的清单，不是永远正确的章节路由；章节变动后更新它及大纲。实际被主文件引用的文件优先（`writing status` 的「被 main 引用」列），勿误写 backup、before_change 或未启用的备用章节。

- `project.md`：研究问题、目标期刊/会议、语言、篇幅和模板要求、已有材料、结论边界。
- `outline.md`：实际 TeX 路径、章节角色、要支持的论点、所需证据和验收条件。
- `zh/<章节>.md`：章节的完整中文稿，与同名 `.tex` 对应。
- `log.md`：每轮一条：意图与原因、动了哪些文件、相关章节的对齐状态、遗留问题与下一步。
- `align.json` 与 `status.md`：中英对齐记录（命令维护，不手改）与生成的状态表。
- 证据、任务包、审查和资料摘录按需写入 `.writing/` 下的文件，不预建空文件夹。

只有用户要求初始化新论文且没有现有 TeX/模板时使用 `--scaffold`。默认编号结构与已有项目适配规则见 [references/project-layout.md](references/project-layout.md)。不要自动拆分或替换已有主文件。

局部改句只需读取相关上下文、简短更新进度并检查改动；无需整篇任务包、无关文献搜索或多代理。

## 2. 中文稿与每轮流程

用户的写作方式是：通过对话把 `.writing/zh/` 里的中文稿写成完整中文版，用户认可后再翻译为英文写入 `.tex`。

- **对应关系**：`zh/1_intro.md` ↔ `sections/1_intro.tex`，按文件名配对；`writing init` 为每个章节 TeX 建一份空中文稿。没有同名 TeX 的中文稿（如 `zh/0_motivation.md`）是纯逻辑文档，不参与对齐。
- **以谁为准**：论证逻辑以中文稿为准，英文措辞以 `.tex` 为准。只润色英文不需要回改中文；TeX 的改动涉及论证（包括合作者在 Overleaf 上的修改）时，先回写中文稿，再对齐。
- **翻译**：按中文稿逐段译入对应 `.tex`，只改有变动的段落。中文稿里的引用键、标签、公式和宏保持 LaTeX 原样（`\cite{key}`、`\ref{fig:x}`、`$...$`），译文原样带入。保留 `.tex` 现有的模板命令、修订标记和注释约定。
- **不靠文件名留版本**：中间稿（如 `3_method_adapted.md`）用完即并入正式中文稿或删除；历史在 `.writing` 的 Git 里。

一轮指一个修改意图，例如「重写引言第二段的研究缺口」。每轮按以下顺序：

1. `overleaf-ctl pull ALIAS`，再 `overleaf-ctl writing status ALIAS`。先处理「英文领先」或「两边都改」的章节：判断 TeX 的改动是否涉及论证，涉及就回写中文稿。
2. 与用户讨论，修改中文稿。用户要求先谈中文逻辑时，不提前写英文。
3. 中文定稿后翻译进 `.tex`，需要时编译检查。
4. 对两边已一致的章节运行 `overleaf-ctl writing align ALIAS -s 1_intro`（可重复 `-s`）；确认英文只是措辞改动时同样用 `align`。
5. 收尾：写一条日志。首行是一句话意图（作标题和 `.writing` 的提交说明），后续行写原因、关键决定、遗留问题和下一步；命令自动列出改动文件和章节状态，并提交 `.writing`，日志不抄 diff。用户授权发布时再用同一句意图 sync。

   ```bash
   overleaf-ctl writing log ALIAS -m "重写引言第二段的研究缺口
   原因：……；遗留：……；下一步：……"
   overleaf-ctl sync ALIAS --message "重写引言第二段的研究缺口"
   ```

局部改句也走这个流程，只是第 2–3 步很短；纯英文润色可以跳过第 2 步，在第 4 步对齐。

## 3. 先整理证据，再写正文

引言、相关工作和新增文献性论断，先按 [references/evidence.md](references/evidence.md) 整理 `.writing/evidence-map.md` 和当前章节的段落蓝图，再写进对应 `.tex`。已有证据表足够时复用并只补变化。

优先消费用户资料和已核验文献。引用必须支持所写的具体论断；检索元数据或 DOI 存在不能证明文章支持某项结论。全文不可用时限制在已读摘要或摘录范围；不能补造实验细节或文献。缺依据的论断留在本地档案作为问题，不写成已证实事实。

方法、实验与结果使用用户提供的数据和实验日志。把来源、统计口径、图表映射及允许的结论记录在 `.writing/`；任何布局演示数据只留本地并明确标注，不混入可提交的实验结果。

## 4. 贡献主线与反防御性表达

有了证据和段落蓝图后，按 [references/anti-defensive.md](references/anti-defensive.md) 确定证据支持的核心价值，减少防御前缀、无依据的自我贬低与实验流水账。整篇任务或主线重组时按需维护 `.writing/narrative.md`；局部改句只做相关检查。

明确表达研究的贡献，保留影响结论的不利结果、必要限定和合理不确定性；不为突出优势改换预设指标、隐藏基线或编造取舍理由。此规则同时进入章节任务包和内容审查。

## 5. 分章执行与审查

整篇起草或实质重写：按 [references/chapter-workflow.md](references/chapter-workflow.md) 给每个主要章节创建任务包，分派独立子代理，各自独占一个章节文件；主代理负责结构、共享文件和最终审查。子代理不可再次分派整篇，也不可操作 Git 推送。

单章任务可直接执行，但都要经过两类检查：

- 规范检查：完成本轮要求、改对活动章节、符合模板、标签/引用/依赖完整，必要时编译。
- 内容检查：论断有支撑、论证连贯、术语与其他章节一致、实验条件与结论边界准确，没有过程提示混入正文；反防御改写没有夸大贡献或遗漏关键结果。

任何检查失败先修复或准确记录阻碍，不靠字数、引用数量或禁词命中率声称学术质量达标。保持自然、具体的论文表达，不为去 AI 化删除事实或限定条件。

## 6. 完成与同步

用 `writing log` 记录本轮：改了哪些中文稿和 TeX、用了哪些证据、做了哪些检查和仍缺什么。需要 PDF 时调用工具层编译并检查引用/交叉引用警告及布局；编译成功仅表示构建成功。

写作过程产物全部留在 `.writing/`，构建产物在 `.outputs/`。实际用于论文的图片、表格和 bibliography 留在项目原有路径。中文稿只放在 `.writing/zh/`，不要在论文目录里另建 Markdown 章节稿、独立 LaTeX 输出树或默认上传审查报告。

用户要求发布时加载 [../tools/SKILL.md](../tools/SKILL.md)，审查改动后使用受保护的同步命令。初始化与写作不自动推送。
