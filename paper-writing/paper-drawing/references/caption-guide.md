# Caption guide

Gather the context before writing:
1. The slide text: `pdftotext -layout -f P -l P deck.pdf -` (column/row labels, method names, prompts).
2. The paper: existing captions of figures with the same layout (`grep -n -A6 '\\caption' sections/*.tex`), the method's name/macro, baseline spellings, and the paragraph that discusses this experiment (and whether it already cites the figure).

## Rules

- **Match the paper's style.** For CVPR/ICCV this is usually `\textbf{Short title.}` followed by 1–3 sentences. Use the paper's exact method and baseline spellings and its terminology, even if the slide differs (slide "Minimax-H3" → paper "MiniMax-H3"). Report every such normalisation.
- **Layout sentence**: say what the rows, columns and groups are, where the prompt and references sit, and what highlights, boxes or arrows mean, so the reader can parse the figure without the text.
- **Takeaway sentence**: point to the observable difference (identity, clothing details, motion, instruction following, artifacts). Describe what is *visible*. Don't introduce numbers or claims that aren't already supported in the paper.
- **Series of same-layout figures**: every caption must stand on its own. Never write "Layout as in Fig. N" or "Same as above"; readers jump straight to a figure, and a pointer caption reads as unfinished. Instead:
  - give each figure a **content title** instead of a bare number: "…: single-character scenes", "…: two-character interactions", rather than "(I)/(II)";
  - restate the layout in one short clause ("Videos generated by Ours, B1, B2, and B3; prompt and references in the bottom row of each group"). Give the full explanation (e.g. what bracketed indices mean) in the first figure only;
  - add what is specific to this figure: its scenes and its reference types or counts, read from the slide text.
- **Editing captions in an existing `.tex`**: change them per float environment (find the `figure`/`figure*` block containing the `\label`, then edit its `\caption` line). Never run a file-wide non-greedy regex from `\caption{` to a label; it can swallow neighbouring blocks. Run `sync_figures.py` afterwards: any "inserted new block" for a label that already existed means a block was lost.
- **Labels**: `fig:<semantic_id>`, matching the file name (`fig_appx_qual_comparison_1.pdf` ↔ `fig:appx_qual_comparison_1`). Reference every new figure with `\cref` from the text. In an appendix, use one lead-in sentence for the whole subsection.
- Keep the caption in **one canonical place**. After the first insertion that is the `.tex`, not the manifest.
- Flag inferred claims for the user to confirm (e.g. "after RL better preserves identity").

## Templates

Qualitative comparison grid, first of a series (full layout):
```latex
\caption{\textbf{Additional qualitative comparison: <content title>.} Each group shows videos generated by <Ours>, <B1>, <B2>, and <B3>, with the multimodal prompt and reference images in the bottom row; bracketed indices in the prompt refer to the reference images. <What these examples contain>. <One visible takeaway>.}
```
Later figures in the series (self-contained, short):
```latex
\caption{\textbf{Additional qualitative comparison: <content title>.} Videos generated by <Ours>, <B1>, <B2>, and <B3> in <scene list>. Each example is conditioned on <reference types>, shown in the bottom row of each group.}
```
Before/after (ablation):
```latex
\caption{\textbf{Effect of <component>.} With the same prompt and references, <variant B> better preserves <visible property> than <variant A>.}
```
Method / pipeline:
```latex
\caption{\textbf{Overview of <Method>.} (a) <stage>. (b) <stage>. <one sentence on the key mechanism>.}
```
